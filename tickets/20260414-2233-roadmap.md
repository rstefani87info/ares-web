# Roadmap Migliorie aReS Web

## Obiettivo
- Consolidare `@ares/web` come libreria framework con API stabili, default sicuri e integrazione prevedibile nei progetti consumer.

## v1.0.x Stabilizzazione Core
- [x] Correggere i bug runtime in `jwt.js` e rimuovere le dipendenze implicite da struttura applicativa esterna.
- [x] Correggere i bug bloccanti in `swagger.js` per rendere il modulo almeno eseguibile e verificabile.
- [x] Correggere `permissions.js` per applicare regole coerenti su risorsa, actor context e deny-list.
- [x] Rendere `sendError()` e il logging di `server.js` sicuri per una libreria, con diagnostica opzionale e non invasiva.
- [x] Sistemare `isProduction()` e `normalizeMethodsArray()` per eliminare errori logici di base.

## v1.1 Contratto Pubblico
- [ ] Definire la superficie pubblica del pacchetto: entrypoint, moduli esportati e API supportate.
- [ ] Formalizzare il contratto di `aReSInitialize`, `exportRESTRoute`, `validateJWT`, `getRoutes` e `isResourceAllowed`.
- [ ] Ridurre o incapsulare gli accessi a dettagli interni di Express come `_router.stack`.
- [ ] Trasformare gli override di response e i comportamenti diagnostici in hook o middleware opzionali.

## v1.2 Configurabilita
- [ ] Esporre configurazione esplicita per `cors()`, `express.json()` e `express-session`.
- [ ] Definire default conservativi e override semplici per i consumer del framework.
- [ ] Chiarire se l'auto-export delle datasource REST debba essere opt-in o configurabile per ambiente.
- [ ] Distinguere opzioni obbligatorie, opzionali e fallback in `appSetup`.

## v1.3 Packaging e Publish
- [ ] Allineare `package.json` all'entrypoint reale della libreria.
- [ ] Separare `dependencies`, `peerDependencies` e moduli opzionali in base al loro uso effettivo.
- [ ] Valutare entrypoint secondari per feature non core come Swagger code generation.
- [ ] Verificare che gli import monorepo funzionino anche dopo publish del pacchetto.

## v1.4 Qualita e Adozione
- [ ] Aggiungere test di smoke su bootstrap server, route export, permessi e JWT.
- [ ] Aggiungere test mirati su Swagger e sulle utility HTTP piu' fragili.
- [ ] Aggiornare `README.md` con quick start, configurazione minima e pattern consigliati di integrazione.
- [ ] Documentare compatibilita', API stabili e punti di estensione previsti.

## Backlog
- [ ] Verificare la stabilita' e la dimensione di header custom come `X-aReS-Metadata`.
- [ ] Valutare la scomposizione di moduli accessori per ridurre il peso del pacchetto base.
- [ ] Introdurre esempi applicativi separati dalla libreria per evitare coupling tra framework e app host.
- [ ] Valutare una policy di versioning semantico esplicita per le API pubbliche del modulo `web`.
